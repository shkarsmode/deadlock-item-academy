# Данные игры, контент и импорт билдов

## Три вида информации

1. **Данные клиента**: характеристики, цены, тиры, компоненты, описания, способности. Скачиваются
   скриптом, правками руками не меняются. В интерфейсе отмечены как «данные клиента».
2. **Статистика**: популярные предметы героя на высоком рейтинге (частота покупки, процент побед, этап
   матча). Показывает привычки игроков, а не силу предмета.
3. **Контент**: объяснения, ситуации, курсы, разборы билдов. Пишется людьми в `content/`, каждое
   утверждение помечено статусом: `data` (следует из данных клиента), `expert` (экспертная оценка),
   `stat` (статистика), `unverified` (не проверено, показывается с предупреждением).

## Источники

| Что | Откуда |
| --- | --- |
| Предметы (англ. и рус.) | `https://api.deadlock-api.com/v1/assets/items`, `?language=russian` |
| Герои и способности, популярные предметы | `https://api.deadlock-api.com/v1/assets/heroes`, `?language=russian` |
| Пороги вложений, группы магазина | `https://api.deadlock-api.com/v1/assets/generic-data` |
| Версия клиента | `https://api.deadlock-api.com/v1/assets/steam-info` |
| Патчи | `https://api.deadlock-api.com/v2/patches` |
| Иконки | `https://assets-bucket.deadlock-api.com/...` (иллюстрации из магазина игры) |
| Описания способностей, которых нет в API | локальный клиент игры: `game/citadel/resource/localization/citadel_heroes/citadel_heroes_*.txt` |

Данные API извлекаются из файлов клиента игры. Текущая версия: клиент 6864.

## Синхронизация: `npm run data:sync`

Скрипт `scripts/sync-game-data.ts`:

1. скачивает все источники (или читает сохранённые, с `--offline <dir>`);
2. нормализует их общей функцией `normalizeGameData` (`src/app/core/game-data/normalize.ts`): чистит
   разметку описаний, собирает характеристики, компоненты и улучшения, тип активации и imbue,
   считает отпечаток каждого предмета и героя;
3. если найден клиент игры (`--client <dir>`, переменная `DEADLOCK_PATH` или стандартные пути Steam),
   дополняет пустые описания способностей из локализации клиента;
4. сравнивает с прошлой версией и пишет изменения (`changes.json`: добавлено, удалено, изменено,
   со списком изменённых полей);
5. скачивает иконки в `public/game/{items,heroes,abilities}/*.webp` (`--skip-icons` пропускает).

Файлы результата (`public/data/game/`): `meta.json` (версия клиента, пороги вложений, группы магазина,
отпечатки, патчи, источники), `items.json`, `heroes.json`, `changes.json`. По одной записи на строку,
чтобы в git были читаемые различия.

## Контент и перепроверка после патча

`npm run content:validate` (`scripts/validate-content.ts`):

- проверяет каждый файл в `content/`: существование ключей предметов, героев и способностей; бюджет
  ситуации (цена с учётом компонентов), соответствие оценок вариантов и их баллов; что текст вопроса
  не выдаёт ответ; запрещённые символы (длинные тире), HTML, TODO; устаревшие названия предметов;
- сравнивает отпечатки упомянутых предметов и способностей с сохранёнными в `content/pins.json`.
  Если предмет изменился в патче, материал попадает в список «нужна перепроверка после патча»
  (видно в интерфейсе и в настройках);
- собирает `public/data/content/bundle.json`.

Флаги: `--check` (только проверка), `--only <часть имени файла>`, `--repin all` или `--repin <id>`
(принять текущие данные после перепроверки).

Порядок после патча:

```bash
npm run data:sync
npm run content:validate          # покажет, что перепроверить
# правка текстов в content/
node scripts/validate-content.ts --repin <id>
npm run check                     # валидация, тесты, сборка
```

## Обновление прямо в приложении

Настройки, раздел «Данные игры»:

1. «Проверить обновление» скачивает свежие данные из API в браузере и показывает различия;
2. «Установить» сохраняет их в IndexedDB поверх встроенных и помечает изменившиеся предметы:
   они получают приоритет в ближайших тренировках (вопросы на механику);
3. «Откатить» возвращает встроенные данные.

Ручной контент так не обновляется: он приходит только с новым деплоем.

## Импорт билдов

### Из кэша игры

Файл: `Steam/userdata/<Steam id>/1422450/remote/cfg/cached_hero_builds.kv3`
(1422450 это id Deadlock в Steam). Формат: бинарный KeyValues3 версии 5 со сжатием LZ4, внутри
сообщения protobuf `CMsgHeroBuild`. Декодер написан с нуля (`src/app/domain/builds/import/`) и работает
в браузере, файл никуда не отправляется. Видны все билды в кэше: свои и скопированные, с категориями,
порядком, imbue-целями и пометками.

### По id публичного билда

`https://api.deadlock-api.com/v1/builds?build_id=<id>&only_latest=true`. Отправляется только id.

### JSON (`dia-build`)

```json
{
  "format": "dia-build",
  "version": 1,
  "hero": "hero_hornet",
  "name": "Мой билд",
  "description": "необязательно",
  "categories": [
    {
      "name": "Лайн",
      "items": [{ "key": "upgrade_extra_charge" }, { "key": "upgrade_high_velocity_mag" }]
    },
    {
      "name": "Ситуативно",
      "optional": true,
      "items": [{ "key": "upgrade_quick_silver", "imbue": "citadel_ability_hornet_sting", "note": "imbue на Crow Familiar" }]
    }
  ]
}
```

`imbue` нужен только предметам с imbue и указывает способность. `hero`, `key` и `imbue` это внутренние имена (`hero_hornet` это Vindicta, `hero_necro` это Graves); их видно
в адресе карточки предмета (`/items/upgrade_...`). Импорт также принимает JSON билда в формате
deadlock-api (`hero_build`).

### Вручную и по скриншоту

Ручной редактор с поиском предметов. Помощник по скриншоту: обводишь иконку на скриншоте, приложение
сравнивает её цветовой рисунок с иконками всех предметов и предлагает ближайшие варианты. Это подсказка,
а не распознавание: каждый предмет подтверждаешь сам.

### В игру

Обратного пути нет: Deadlock не импортирует билды из файлов. Приложение не пишет в файлы игры,
не читает её память и не взаимодействует с процессом игры.

## Как добавить контент

Правила и примеры: [CONTENT_GUIDE.md](CONTENT_GUIDE.md). Коротко: только проверяемые утверждения,
у каждого статус, без длинных тире, официальные названия как в игре, ситуация описывает угрозу, бюджет
и уже купленное, у каждого варианта балл и объяснение.
