# Архитектура

Одностраничное приложение на Angular 21 (LTS): standalone-компоненты, signals, zoneless, OnPush,
TypeScript strict. Сервера нет: всё, что нужно для работы, лежит в статических файлах, прогресс
хранится в IndexedDB браузера.

## Слои

```
scripts/            Node-скрипты (запускаются без сборки, через type stripping)
  sync-game-data.ts   скачивание и нормализация данных игры, иконки
  validate-content.ts проверка контента, отпечатки (pins), сборка bundle.json
  serve-dist.ts       локальный сервер для production-сборки
  make-icons.mjs      генерация иконок PWA без зависимостей

content/            контент, который пишут люди (JSON): предметы, ситуации, курсы, разборы билдов, проблемы
public/data/game/   нормализованные данные игры (генерируются sync-game-data)
public/data/content/bundle.json   собранный и проверенный контент (генерируется validate-content)
public/game/        иконки предметов, героев и способностей (webp)

src/app/
  core/       инфраструктура без бизнес-логики
    game-data/  модель данных игры, нормализация (общая со скриптом), загрузка, обновление в приложении
    db/         схема IndexedDB, экспорт и импорт прогресса
    i18n/       русский и английский интерфейс, пайпы для текста и названий из игры
    profile/    профили (несколько человек на одном устройстве), настройки
    ui/         горячие клавиши, уведомления
  content/    модель контента, словари (роли, угрозы, измерения), валидатор (общий со скриптом), сервис
  learning/   обучение: FSRS, уровни освоения, генераторы вопросов, планировщик, сессия, аналитика
  domain/builds/  модель билда, анализатор, импорт (KV3, protobuf, JSON, публичный id)
  features/   экраны (ленивые маршруты), по папке на раздел
  shared/ui/  переиспользуемые компоненты: иконки, карточки предметов, выбор предмета, примитивы
  testing/    фикстуры для unit-тестов (реальные данные из public/)
```

Код нормализации данных (`core/game-data/normalize.ts`) и валидатор контента
(`content/validate-content.ts`) используются и приложением, и Node-скриптами. Поэтому между такими
модулями только `import type`: Node запускает `.ts` напрямую, без сборки.

## Загрузка приложения

`provideAppInitializer` параллельно:

1. открывает IndexedDB и активный профиль (`Profiles.init`);
2. загружает данные игры (`GameData.load`): `meta.json`, `items.json`, `heroes.json`. Если пользователь
   установил обновление данных из настроек и оно новее встроенного, используется оно;
3. загружает `bundle.json` с контентом (`Content.load`).

Ошибка загрузки данных не блокирует запуск: экран показывает понятное состояние и кнопку повтора.
Маршруты кроме онбординга защищены guard-ом: без пройденного онбординга открывается `/onboarding`.

## Состояние

Сервисы с signals вместо глобального стора:

| Сервис | Что хранит |
| --- | --- |
| `GameData` | предметы, герои, способности, индексы по ключу и id, цены с учётом компонентов |
| `Content` | разборы предметов, ситуации, курсы, разборы билдов, проблемы, список материалов на перепроверку |
| `Profiles` | профили и настройки текущего профиля |
| `Knowledge` | знание по предметам и измерениям, история ответов за 120 дней, показы вопросов, тетрадь ошибок, уровни |
| `Session` | текущая сессия: вопросы, ответы, вставка повторов после ошибок, итоги |
| `Builds` | сохранённые билды и встроенные разборы |
| `MyBuild` | какой билд считается «моим» для персонализации |

Вычисляемые значения (`computed`) пересчитываются только при изменении источников, поэтому экраны
не держат своих копий данных.

## Хранение (IndexedDB, база `deadlock-item-academy`, версия 1)

| Хранилище | Ключ | Содержимое |
| --- | --- | --- |
| `profiles` | id | имя, настройки |
| `knowledge` | [profileId, itemKey] | состояние каждого измерения: карточка FSRS, попытки, серии, ошибочные убеждения |
| `reviews` | авто | каждый ответ: вопрос, предмет, измерение, результат, уверенность, время, герой (индексы по профилю и времени) |
| `exposures` | [profileId, questionId] | сколько раз показан вопрос, последний результат (новые и повторные ситуации) |
| `mistakes` | id | путаницы, ошибочные убеждения, нарушенные принципы, серия исправлений |
| `sessions` | id | итоги сессий |
| `builds` | id | билды пользователя |
| `reflections` | id | записи «после матча» |
| `kv` | ключ | служебное: установленное обновление данных, выбранный билд и т. п. |

Экспорт прогресса: JSON с форматом `dia-progress` версии 1. Импорт в новый профиль или с заменой
текущего. Сброс удаляет данные только текущего профиля.

## Маршруты

`''` главная, `onboarding`, `practice` и `practice/run`, `items` и `items/:key`, `compare`, `scenarios`,
`simulator`, `builds` и `builds/:id`, `active`, `paths` и `paths/:hero`, `analytics`, `mistakes`,
`problems`, `reflect`, `settings`, `share/:code`. Все экраны грузятся лениво. Параметры маршрута
передаются во входы компонентов (`withComponentInputBinding`).

Тренировка и онбординг открываются в режиме фокуса: без бокового меню и нижней панели.

## Интерфейс

- Стили: глобальные токены в `src/styles.scss` (цвета, отступы, радиусы 4-8 px, типографика),
  тёмная тема по умолчанию, стили компонентов рядом с ними.
- Шрифты Inter и JetBrains Mono подключены локально (`@fontsource-variable`), без внешних запросов.
- Иконки интерфейса: lucide, отрисовка inline SVG из массивов узлов (без иконочного шрифта).
- Иконки игры: локальные webp; если файла нет, запасной вариант с CDN.
- Адаптивность: боковое меню на десктопе, узкая колонка на планшете, нижняя панель и лист «Ещё»
  на телефоне, safe area, отсутствие горизонтальной прокрутки проверяется e2e-тестом на 18 экранах.
- Доступность: фокус с клавиатуры, aria-метки, горячие клавиши не мешают вводу в поля.

## PWA

`@angular/service-worker`, конфигурация `ngsw-config.json`:

- `app`: код приложения, кэшируется при установке;
- `data`: данные игры и контент, кэшируются при установке (приложение работает офлайн сразу);
- `game-art`: иконки, кэшируются по мере просмотра или кнопкой в настройках;
- запросы к API и CDN: отдельные группы со своими стратегиями.

Новый деплой приложение замечает при открытии и раз в 6 часов, затем показывает уведомление
с кнопкой «Обновить».

## Тесты

- Unit (Vitest через `@angular/build:unit-test`): чистая логика без браузера, на реальных данных игры.
- E2E (Playwright): `e2e/*.spec.ts`, проекты `desktop` (1366x860) и `mobile` (iPhone 13, Chromium).
  Сервер для тестов поднимается на порту 4300, чтобы не мешать `npm start`.
